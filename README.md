# Thread-per-connection HTTP-сервер

**Версия v0.1**: однопоточный HTTP/1.1-сервер на C++20 и POSIX sockets. Отвечает на `GET /health`, поддерживает keep-alive и корректно завершается по SIGINT/SIGTERM.

Потоки появятся в v0.3. Параметр `--threads` на этом этапе разбирается и проверяется, но не используется.

## Сборка и запуск

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j
./build/server --port 8080 --threads 8
```

| Параметр    | Описание                      |
|-------------|-------------------------------|
| `--port`    | порт для прослушивания        |
| `--threads` | число рабочих потоков (в v0.1 не используется) |

Платформа: Linux x86_64.

## Архитектура

Слои, от нижнего к верхнему:

| Слой | Модуль | Ответственность |
|------|--------|-----------------|
| Сеть | `server` | слушающий сокет, accept-цикл, обёртки над чтением и записью |
| HTTP | `http` | структуры `Request`/`Response`, парсер, сборка ответа. Работает только со строками. |
| Маршрутизация | `router` | функция `Request -> Response` |
| Точка входа | `main` | аргументы, сигналы, запуск сервера |

### Обслуживание соединения (keep-alive)

Цикл на одно соединение:

1. Пока в буфере нет полного запроса, ждём данных через `wait_readable` с таймаутом простоя и читаем. При таймауте, закрытии клиентом или ошибке закрываем соединение.
2. Парсим. При `Incomplete` продолжаем читать. При `Error` отвечаем 400 и закрываем соединение.
3. При `Complete` вызываем роутер, собираем ответ и отправляем.
4. Удаляем из буфера `consumed` байт. Остаток принадлежит следующему запросу, поэтому сразу проверяем, нет ли в буфере готового запроса.
5. Закрываем соединение, если HTTP/1.0 без keep-alive, если пришло `Connection: close` или если выставлен флаг остановки. Иначе возвращаемся к шагу 1.

Исключения внутри цикла ловятся, клиент получает 500.

### Завершение

Обработчик SIGINT/SIGTERM только выставляет `std::atomic<bool>`. Accept-цикл делает `poll` с таймаутом 100–200 мс и регулярно проверяет флаг. После выхода из цикла закрывается слушающий сокет. SIGPIPE игнорируется.

| 4 | Сборка ответа | статусная строка, `Content-Type: application/json`, `Content-Length`, `Connection: keep-alive`/`close`, пустая строка, тело; таблица текстов для кодов 200, 400, 404, 405, 500 | 2 |
| 5 | Роутер | `GET /health` -> 200 `{"status":"ok"}`; неизвестный путь -> 404; известный путь с другим методом -> 405 | 2, 4 |



## Ограничения v0.1

- Сервер однопоточный: соединения обслуживаются строго по очереди.
- Единственный маршрут — `GET /health`.
- Параметр `--threads` не используется.
- Поддерживается подмножество HTTP/1.1: request line, заголовки, `Content-Length`, keep-alive.
